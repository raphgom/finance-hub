# Contribuição

1. Abra uma issue descrevendo mudança e impacto, sem dados financeiros ou credenciais.
2. Crie branch para a correção; preserve isolamento dos workspaces e as invariantes financeiras.
3. Rode `npm run verify` e, quando possível, a demo isolada via Docker.
4. Envie PR com evidências, riscos, migração de esquema e critérios de rollback.
5. Nunca commite `secrets/`, `backups/`, dados reais ou screenshots com informações pessoais.

A definição de licença está pendente de decisão do proprietário. Não interprete a presença do código no GitHub como concessão automática de licença de reutilização.
